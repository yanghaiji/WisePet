## 0. 背景与现状缺口

用户连续反馈三件事，逐条核对代码后确认都不是"描述不够细"，而是功能缺口：

1. 现在聊天只有**一个单行输入条 + 一个一次性气泡**，没有任何地方能看到历史会话；`ChatSession` 是纯内存且 `max_turns*2` 会主动删最早记录，重启即忘。
2. 调用大模型时用户**看不出当前处于哪一步**（排队/请求中/流式出字/已完成/失败），也看不出这条是本地小脑答的还是远端模型答的。日志里有 `source=ai|local`，但界面上没有任何会话状态。
3. 对话期间宠物仍在动：`tick()` 无条件调 `_advance_motion`，重力分支只排除 `DRAGGING`，半空开聊会继续下落；从 `WALKING`/`HURT` 进 `THINKING` 是非法迁移被静默吞掉，点击链路（`on_release→on_click→HURT`）之后发消息，宠物实际还停在 `HURT` 继续走。

## 1. C13 常驻会话窗与按天聊天记录

### R1 会话窗替代单行输入条
点击宠物打开**一个常驻聊天窗**（再点一次收起），窗内含：历史消息区、状态栏、按天日期选择、输入框与发送按钮。原有的单行 `ChatInput` 与宠物头顶一次性气泡仍在（气泡负责拟人播报），但不再承担"看历史"的职责。

### R2 历史会话可见且可回看
历史区展示当天全部对话（用户消息、助手回复、兜底话术），每条带时间戳、角色与来源标签。日期选择可切换到有记录的历史日期；启动与重新打开窗口时自动把当天历史读回。

### R3 会话状态必须可见
状态栏显示：当前会话日期、已记录条数、会话阶段（空闲 / 思考中 / 正在回复 / 回复完成 / 出错了）、以及**当前大脑来源**（大模型 / 本地小脑）。失败时附错误类别。启动与保存配置后即显示来源，不必等第一条消息。

### R4 聊天记录按天保存
用户消息与每一条完整回复（含兜底话术）都落盘到 `~/.WisePet/chat/YYYY-MM-DD.json`，**只追加不截断**，与发给模型的上下文窗口（`ChatSession`）彻底分开。跨天自动写新文件；文件损坏自动备份并当空处理，程序不崩。

### R5 记录内容与隐私口径
记录的是**完整回复**而非流式增量，不把半截句子写进历史；空白消息、空回复不记。用户输入的原文此前不进日志，本版本起会随聊天记录落到本机文件——这是用户明确要求的"聊天记录保存"，需在界面/文档如实告知。

### R6 分层与可测
聊天窗不得直接读写 infra 仓储；记录读写经 app 层门面与组装根注入的回调。按天归档键是单一真相源，本地时区。

### 验收项
- AC-CHAT-1：点击宠物打开聊天窗，输入并回车发出消息，历史区立刻出现该条用户消息。
- AC-CHAT-2：不配 API Key 发一句，状态栏显示"思考中/正在回复/回复完成"且大脑为"本地小脑"；配好 Key 后显示"大模型"。
- AC-CHAT-3：网关超时时状态栏显示"出错了（timeout）"一类可读错误，历史里保留一条兜底回复。
- AC-CHAT-4：重启应用后当天历史仍在会话窗；跨天后新对话写进新文件、旧文件不变且条数不减。
- AC-CHAT-5：删掉某天文件改成损坏 JSON，启动不崩且该文件被备份。
- AC-CHAT-6：会话窗中显示的用户文本含 `<`/`&` 等字符时按纯文本呈现，不被当成 HTML 执行。

## 2. C14 对话期间宠物原地不动

### R7 会话窗口打开即冻结
聊天窗打开期间：不自主溜达、不启动新的一次性行为、不贴地重力下落、不被提醒 `move_to` 拽向鼠标；关闭窗口后全部恢复。`THINKING`/`SPEAKING` 状态即使窗口被关也保持冻结，直到气泡关闭回 `IDLE`。

### R8 进入对话必须先归一化状态
从 `WALKING`/`RUNNING`/`HURT`/`EATING`/`STRETCHING`/`SLEEPING`/`SAD`/`SPEAKING` 发消息都要能进入 `THINKING`；拖拽中不打断（用户的手优先）。状态机白名单（不变量 I1）不放宽，由 app 层编排收回到 `IDLE` 再迁移。

### 验收项
- AC-STILL-1：走动中点宠物、打开聊天窗并发消息，宠物进入 `THINKING` 且坐标在整个回复过程中不变。
- AC-STILL-2：半空（开启贴地）打开聊天窗，重力不再把宠物往下拽；关窗后恢复下落。
- AC-STILL-3：对话期间到达的喝水/久坐提醒不会把宠物移到鼠标旁。

## 3. 不作废的旧约束

- v1.6 C8 的日志口径不变：`source=ai|local`、摘要、脱敏继续生效；本版本新增的**界面来源标签**与"气泡不加来源标记"不冲突——来源只出现在聊天窗状态栏，气泡保持拟人。
- v1.1 C2：未配 Key 仍能聊天，本版本不得把"配了 Key"当隐含前提。
- v1.7 C12 睡眠回血、v1.7 §0.1 补登的 C9~C11 继续有效。
