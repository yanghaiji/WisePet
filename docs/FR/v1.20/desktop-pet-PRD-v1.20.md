# 桌面宠物 WisePet 需求设计 v1.20

- **对应技术设计**：[NFR v1.21](../../NFR/v1.21/desktop-pet-tech-design-v1.21.md)
- **上一版本**：[v1.19](../v1.19/desktop-pet-PRD-v1.19.md)
- **状态**：已实现（待评审）
- **变更性质**：开机体验与通知来源标识四项（打开宠物第一眼的一切都要自洽）

## 0. 背景

此前的开机链路存在三处「自相矛盾」：宠物一睁眼就拉着脸喊「求助·好困呀」，而同一时刻又推送「新的一天，活力满满」的问候——情绪劈叉；系统通知顶部显示的是宿主进程名 `python`，用户看不出是谁在说话；出场特效平淡，与「科技感桌宠」的定位不符。本版把这四处一次性理顺：**开机即元气、问候有口号、通知认得出、出场有科技感**。

---

## 1. C34 开机昂扬问候

### R1 每次打开宠物主动问候一句
启动完成后，宠物**主动推送一句积极昂扬的开场口号**（走既有气泡 / 系统通知 / TTS 通道），标题「开启新的一天」，唤醒主人开启新一天。

### R2 有 AI 用 AI，无 AI 用兜底
配了模型 Key 时调用 AI 生成口号（不超过 30 字，直接输出正文）；**未连模型或生成失败**时回落固定文案：「{宠物名}来召唤你啦，让我们开启美好的一天吧！」——把宠物名字召唤出来，仍是一句完整问候。

### R3 绝不拖慢冷启动
问候在**后台线程**生成，经事件桥投递回主线程上屏；生成过程不阻塞开机，任何异常都退回兜底语，保证「问候必达」。

### 验收项
- AC-GREET-1：每次启动推送一条标题为「开启新的一天」的问候。
- AC-GREET-2：未配 AI Key 时使用含宠物名的兜底文案。
- AC-GREET-3：配了 AI Key 时采用 AI 生成口号；AI 报错时回落兜底。
- AC-GREET-4：问候异步生成，不影响启动耗时。

## 2. C35 系统通知来源标识

### R1 通知归属显示为 WisePet
开启系统通知后，通知中心 toast 上方的**应用名（tile）固定显示 `WisePet`**，不再暴露宿主进程名 `python`。

### R2 正文标题为宠物名
toast 内的粗体首行（标题）显示**宠物名**（无事件自带标题时），让「谁在跟我说话」一目了然。应用名与宠物名各就各位、互不串位。

### R3 尽力而为
在非 Windows 平台或设置应用标识失败时静默跳过，不影响通知照常发出；改名后下一条通知即采用新宠物名。

### 验收项
- AC-NOTIFY-4：通知 tile 显示 `WisePet` 而非 `python`。
- AC-NOTIFY-5：toast 粗体标题为宠物名（或事件自带标题）。
- AC-NOTIFY-6：非 Windows / 设置失败时通知仍正常发出。

## 3. C36 开机元气启动（消除开机求助）

### R1 任一维度低于基线一律托底
开机恢复宠物时，饱食 / 心情 / 精力**任一维度低于元气基线（60）即抬到基线**（只升不降）。回来看到的是精神好的宠物，而不是一睁眼就喊饿喊困、拉着脸。

### R2 不补算关机期间的离线衰减
把 `last_updated` 归一到当前时刻，**关机期间不计离线衰减惩罚**——开机即「全新的一天」，与元气问候口径一致，不再出现「活力满满」与「好困呀求助」同屏劈叉。

### R3 只改开机一次性口径
运行期间的正常衰减、睡眠回血、低落求助逻辑全部不变；本条只约束「开机恢复」这一次。

### 验收项
- AC-FRESH-1：旧快照三维见底时，开机后均被抬到 ≥60。
- AC-FRESH-2：开机后紧跟一次 `tick` 不再发出「求助」事件。
- AC-FRESH-3：三维均高于基线时开机不人为抬高（只升不降）。

---

## 4. C37 出场动画科技感增强

### R1 出场比退场更绚丽
开机出场（spawn）特效在原有「粒子汇聚 + 末段光晕」基础上，新增**汇聚能量环**（两圈由外向内收缩锁定中心）、**旋转扫描环**（四段短弧如仪表扫描锁定）、**收尾白核爆闪**（一次正弦脉冲闪完即隐，宠物正好淡入现身）。

### R2 时长更从容
出场时长由 700ms 延长到 **950ms**，让汇聚、扫描、爆闪三段有展开空间；退场（exit）保持 700ms 不变。

### R3 纯程序化、零素材
全部由 QPainter 程序化绘制，30fps，不引入任何额外素材依赖。

### 验收项
- AC-FX-1：出场各阶段（起 / 中 / 环 / 扫描 / 爆闪）绘制均不报错。
- AC-FX-2：出场时长（950ms）大于退场时长（700ms）。
- AC-FX-3：特效驱动到超时后发出 `finished`，宠物随后淡入。

---

## 5. 不作废的旧约束

- 通知走系统中心与否仍由 `notification.use_system` 决定，关闭时维持头顶自绘气泡。
- 开机仍遵循 PRD 冷启动 <3s 目标；问候、托底、特效都不改状态机白名单与事件契约。
- C30~C33（TTS / 系统通知 / 周报 / 成长）全部行为不变，本版仅在其之上理顺开机与标识。
