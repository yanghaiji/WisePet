# 桌面宠物 WisePet 需求设计 v1.15

- **对应技术设计**：[NFR v1.16](../../NFR/v1.16/desktop-pet-tech-design-v1.16.md)
- **上一版本**：[v1.14](../v1.14/desktop-pet-PRD-v1.14.md)
- **状态**：待评审
- **变更性质**：行为轮询缺陷修订（不改状态机白名单与事件契约）

## 0. 用户反馈与实证

> 「我感觉现在的轮询还是有问题 我看不到小猫的其他状态」

用 offscreen 探针按真机节奏模拟 5 分钟（1s 主 tick + 50ms 运动 tick），结论是**轮询链路没坏，节奏坏了**：

| 项 | 修复前 |
|---|---|
| 状态切换 | 41 次；`animator.action` 与 `pet.state` 每次都一致 |
| 分布 | `WALKING` 166.3s（55%）、`IDLE` 108.1s（36%）、`RUNNING` 17.6s、`STRETCHING` 8.0s |
| 交互态 | `EATING` / `HURT` / `THINKING` / `SPEAKING` / `SLEEPING` / `SAD` 全部 0 次（本就只在交互或特定条件下出现） |
| 异常 | 出现 `WALKING→IDLE` 仅 0.05s 的闪断；趟与趟之间 `IDLE` 常只停 0.6s |

根因逐条：① `walk_max_s` 只在「撞到屏幕边缘」时才判，宽屏上走到边要十几秒，上限形同虚设；② `_next_action_at` 只在触发自主行为时排期，一趟二三十秒后早已过期，一回到 `IDLE` 下一拍立刻又出发；③ 上一趟正好停在边界，下一趟朝外起步第一步就「到边」被随机收趟；④ 一次性动作只有 0.75~1s 且收场靠 1s 主 tick；⑤ 状态变化只发事件、没有任何 INFO 日志，用户无法自证「到底切没切」。

## 1. C25 轮询节奏与状态可观测

### R1 每拍判时长
`walk_max_s` 在每个运动拍都检查，走满即收趟；到边折返仍保留随机提前收场与「跑累先降回走」的既有玩法。

### R2 收场后重新排空闲
一趟溜达或一次性动作结束回 `IDLE` 时重排 `_next_action_at`，让宠物真的按 `idle_min_s~idle_max_s` 休息几秒，其它状态才有出场机会。

### R3 贴边起步朝内
正好停在左右边界时强制朝屏幕内侧起步，消除 0.05s 闪断；离边还有几步时仍尊重随机方向，不破坏到边折返。

### R4 一次性动作要看得见
`STRETCHING` 0.75s → 1.5s、`HURT` 1.125s → 1.5s（按整圈时长向上补齐，接缝不跳帧）；`EATING` 1.8s 不变。

### R5 状态可观测
每次行为迁移写一条 INFO 日志 `behavior A -> B`，用户可在 `~/.WisePet/logs/WisePet.log` 直接确认轮询是否在跑、切到了哪个动作（规约 §2.10）。

### R6 交互态的触发路径要说清
`EATING`（投喂）、`HURT`（点宠物）、`THINKING`/`SPEAKING`（聊天）、`SLEEPING`（夜间+低精力）、`SAD`（心情低于阈值）**不会由自主轮询产生**；聊天输入条 / 历史窗开着会冻结全部自主行为，按 Esc 关闭即恢复。这些写进用户文档。

### 验收项
- AC-POLL-1：走满 `walk_max_s` 即使没撞边也收趟；一趟不超过配置上限。
- AC-POLL-2：收趟后在空闲间隔内不会立刻又出发。
- AC-POLL-3：正好贴边起步时朝向屏幕内侧，不出现 0.05s 的走→停闪断。
- AC-POLL-4：伸懒腰至少驻留 1.5s，收场仍按整圈对齐。
- AC-POLL-5：每次状态迁移在日志里可见 `behavior A -> B`。
- AC-POLL-6：既有 64 项控制器测试与全仓回归全部继续通过。

## 2. 不作废的旧约束

- 状态机白名单、`LOCKED_STATES`、拖拽优先、对话冻结（FR v1.8 C14）全部不变。
- 逐动作帧率 `FPS_BY_ACTION`、一次性动作按整圈收场（NFR v1.8 / v1.9）不变。
- FR v1.14 C24 及更早的聊天 / 素材口径不变。

## 3. 范围外

- 新增自主动作种类（白天打盹、主动撒娇等）——需要新素材与状态语义，另行评审。
- 把活跃度参数（`walk_max_s` / `stretch_trigger_p` / `run_trigger_p`）暴露到设置窗。
- 全局热键唤出指定动作。
