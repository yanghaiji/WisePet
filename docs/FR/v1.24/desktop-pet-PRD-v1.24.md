## 1. C41：系统配置分区，日志参数可设置

v1.23 把日志级别 / 10 MiB 分割 / 3 天保留写成了代码常量。用户要求「做成可以设置的」，
并在设置窗**单独加一个「系统配置」分区**，专门放这些与宠物本身无关的运行参数。

| 编号 | 需求 | 验收项 |
|---|---|---|
| R1 | 设置窗新增「系统配置」分区，与 AI / 人设 / 宠物参数 / 提醒 / 陪伴 / 体验与隐私分开 | AC-SYS-1：分区数 7、控件可滚动、滚轮扫过数值框与下拉只滚页面不改值 |
| R2 | 四项可配置：日志级别、单文件上限（MiB）、保留天数、错误档开关 | AC-SYS-2~4：四控件回填当前值、保存后 `collect()` 输出正确且不丢 `api_key` / 皮肤等其它分节；非法 json 值回落安全默认（级别白名单、1~100 MiB、1~30 天） |
| R3 | **保存后立即生效，不需要重启** | AC-SYS-5：改配置后文件 handler 的 `maxBytes` / `retention_days` / 级别与错误档数量立即变化；日志里留一行 `system log settings applied: …` 供核对 |
| R4 | 下次启动也保持 | AC-SYS-6：启动装配日志前先读 `config.json` 的 `system` 分节，配置值不因重启回默认 |
| R5 | 不影响其它保存路径 | AC-SYS-7：系统配置没变化时（例如只改走速）**不重建**日志 handler；`setup_logging()` 返回主档路径的既有契约不变 |

## 2. 配置项定义

| 配置项 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `log_level` | `info` | `debug` / `info` / `warning` / `error` | 决定根 logger 级别；选 `error` 时主档也只收 ERROR |
| `log_max_mb` | `10` | 1~100 | 单文件分割阈值（MiB），跨天仍会额外封存一次 |
| `log_retention_days` | `3` | 1~30 | 滚动备份按 mtime 清理，正在写的文件不动 |
| `log_split_by_level` | `true` | true / false | 关掉就只写 `WisePet.log`，不生成 `WisePet-error.log` |

均落在 `~/.WisePet/config.json` 的 `system` 分节，可读可手改；解析失败一律回默认值，不崩。

## 3. 边界

- 不新增依赖、不改日志行格式、不改 `main.py` 之外的日志调用点、不动聊天记录数据库与其它持久化。
- 「系统配置」是**容器**：当前只放日志四项，以后开机自启、性能告警、发布通道等系统级开关都归这个分区，
  不再散落到宠物参数里。本版不实现那些尚未存在的功能。
- 不把日志参数做成运行时全局单例：仍由 `AppConfig` 传递，保持 domain 零依赖与可测试性。
