## 0. 背景

v1.10 把聊天入口拆成「点击宠物浮出单行输入条」后，暴露两个体验缺口：

1. 输入条召之即来、却**挥之不去**——用户点开又不想聊时，它一直挂在桌面，要手动 Esc 或点别处才收；
2. 「截图问小墨」只能整屏或手动贴图，**没法只框选感兴趣的那一块**，多模态问答的输入很笨重。

本版补上这两处，让「随手问一句、随手截一块」成为自然动作。

## 1. C28 聊天输入条空闲自动隐藏

### R1 无交互超时自动收起
输入条处于显示状态、且连续无交互超过 `chat.idle_hide_s` 秒后**自动收起**，不需要用户手动关。

### R2 任何交互都重新计时
以下动作都会把空闲计时归零重开：打开输入条、在框内输入、发送一条消息、会话阶段变化（收到回复/进入下一步）。即「用户还在用」就不收，「晾在那儿」才收。

### R3 可配置、可关闭
时长在设置窗「宠物参数」分区以「聊天框空闲隐藏」数值框配置，范围 0~600 秒，默认 30 秒；填 **0 表示不自动隐藏**（保持旧行为）。

### R4 收起即解冻
自动隐藏与手动关闭走同一条收起路径：收起后释放「对话期间宠物原地不动」的冻结（沿用 v1.8 C14 / v1.10 的 `active_changed` 口径），宠物恢复自主行为。

### 验收项
- AC-IDLE-1：显示后静置超过 `idle_hide_s` 秒自动隐藏；期间不隐藏宠物本体。
- AC-IDLE-2：输入 / 发送 / 阶段变化任一发生都重置计时，不会聊到一半被收起。
- AC-IDLE-3：`idle_hide_s=0` 时永不自动隐藏。
- AC-IDLE-4：设置里改时长保存即生效，无需重启。
- AC-IDLE-5：自动隐藏后宠物位移/自主行为恢复正常（与手动关闭一致）。

## 2. C29 截图问小墨（区域框选）

### R1 一键进入框选
托盘 / 右键菜单新增「截图问小墨」入口。点击后整屏画面**冻结变暗**（盖一层进入前抓好的主屏快照，看起来像画面被冻住），光标变十字。

### R2 拖拽框选出图
按住左键拖出橡皮筋选区，选区外四向压暗、选区用主题橘描边高亮；**松手即截取该区域**，作为图片附件自动带入聊天输入并发送问答。

### R3 误触与取消
- 选区宽或高小于 8 像素视为误点，**丢弃不截**；
- 按 **Esc** 取消整个流程，画面恢复，不产生任何附件。

### R4 与既有附件链路一致
框选结果走的是既有的「图片附件 → 多模态请求」通道（与输入条 Ctrl+V 贴剪贴板截图同源），不新增独立的消息格式；未配置视觉模型时按既有附件降级口径处理。

### R5 范围限制（如实登记）
当前只覆盖**主屏**：多显示器环境下冻结与框选都取主屏画面。副屏框选列入范围外。

### 验收项
- AC-SHOT-1：入口触发后出现全屏冻结遮罩，可拖拽框选。
- AC-SHOT-2：松手后选区被裁成图片附件并进入问答，遮罩关闭。
- AC-SHOT-3：选区 <8px 不触发截图；Esc 取消且不产生附件。
- AC-SHOT-4：框选走既有图片附件通道，不改变消息数据结构。

## 3. 不作废的旧约束

- 状态机白名单、数值语义、会话事件契约、按天记录格式全部不变。
- v1.10 C18「聊天界面跟随宠物」、C19「历史窗可继续对话」不受影响：自动隐藏只作用于单行输入条，历史窗不因空闲被收起。
- 输入条 Ctrl+V 贴剪贴板截图的既有能力保留，与区域框选并存。

## 4. 范围外

- 副屏 / 多显示器框选。
- 框选后的涂抹标注、箭头、文字水印等二次编辑。
- 历史窗（只读回看窗）的空闲自动隐藏。
