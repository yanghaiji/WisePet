# 桌面宠物 WisePet 需求设计 v1.11

- **对应技术设计**：[NFR v1.12](../../NFR/v1.12/desktop-pet-tech-design-v1.12.md)
- **上一版本**：[v1.10](../v1.10/desktop-pet-PRD-v1.10.md)
- **状态**：待评审
- **变更性质**：缺陷修订（不改聊天/动画/状态机口径）

## 0. 用户反馈与缺陷定位

> 「隐藏后的宠物我不知道去哪里找呀，这个功能对吗 还是一点没实现」

**不是一点没实现，是缺了恢复入口。** 逐项核对：

| 已有 | 缺失 |
|------|------|
| `toggle_visible()` 隐藏窗口、停帧轮询、收起两个聊天界面与气泡 | 隐藏后屏幕上**没有任何可右键的地方** |
| 菜单文案会切成「显示宠物」（`PetMenu.set_hidden_state`） | 该动作**点不到**：`PetMenu` 只由 `PetWindow.contextMenuEvent` → `context_requested` → `popup()` 唤出，而宠物窗口已经 `setVisible(False)` |
| 「退出」可用 | 全仓零 `QSystemTrayIcon`；进程没有常驻入口 |

`NFR v1.1` 曾登记「系统托盘图标未做，`QMenu` 承担同等入口职责，可接受」——这个假设不成立：`QMenu` 必须依附于一个能接收右键的可见窗口，隐藏后它自己也点不出来。本版本取代该条，按「不回改历史版本」规约只在新文档登记。

## 1. C21 隐藏之后必须能召回

### R1 常驻系统托盘图标
进程启动即在系统通知区/菜单栏显示 WisePet 图标，图标取当前皮肤的 idle 帧；宠物隐藏时图标仍在。

### R2 托盘菜单复用同一份 `PetMenu`
托盘右键菜单就是宠物右键菜单，不另造一份；「隐藏宠物 / 显示宠物」文案与 tooltip 由同一个 `set_hidden_state()` 口径同步，避免出现两份状态真相。

### R3 点击图标即切换
单击 / 双击托盘图标都切换宠物可见性（最直觉的「把它找回来」）；右键（Context）只弹菜单，不重复翻转显隐。

### R4 隐藏不能顺带退出进程
`QApplication.setQuitOnLastWindowClosed(False)`：宠物窗是唯一的可见窗口，隐藏后事件循环必须继续跑衰减、提醒与状态落盘；「退出」仍由菜单显式触发。

### R5 托盘不可用时绝不把用户锁死
平台不提供系统托盘时（含 offscreen 测试环境），禁用「隐藏宠物」动作并在 tooltip 说明原因，不是隐藏完再让用户找不到。可用性可注入，便于自动化验证两条路径。

### R6 既有隐藏行为不变
停帧轮询 / 恢复帧轮询、收起聊天界面、主 tick 不停、状态按间隔落盘（NFR v1.8 §）全部沿用。

### 验收项
- AC-TRAY-1：启动后托盘图标存在，右键弹出的菜单与宠物右键菜单是同一个。
- AC-TRAY-2：隐藏宠物后托盘仍在，菜单显示「显示宠物」，tooltip 标注已隐藏。
- AC-TRAY-3：隐藏后点菜单「显示宠物」，宠物重新出现且帧轮询恢复。
- AC-TRAY-4：隐藏后单击 / 双击托盘图标也能恢复；右键只弹菜单不改显隐。
- AC-TRAY-5：隐藏状态下事件循环不退出，衰减 / 提醒 / 落盘照常。
- AC-TRAY-6：托盘不可用时「隐藏宠物」被禁用且给出原因，不会把用户锁死。

## 2. 不作废的旧约束

- FR v1.10 C18~C20（浮窗跟随 / 历史窗继续聊 / 气泡风格统一）与 C16/C17 全部继续有效。
- FR v1.8 C13/C14、v1.9 C15、v1.7 C12、v1.6 C8、v1.5 C7 口径不变。
- 隐藏时收起聊天 UI、停帧轮询以压低空闲 CPU 的既有取舍不变。

## 3. 范围外

- 托盘气泡通知 / 消息计数角标、托盘图标随状态变化（本期只用静态 idle 帧）。
- 开机自启、全局热键唤醒、多宠物实例各自的托盘图标。
- 自定义托盘图标素材（沿用当前皮肤帧，零新增素材依赖）。
