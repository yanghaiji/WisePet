# 桌面宠物 WisePet 需求设计 v1.17

- **对应技术设计**：[NFR v1.18](../../NFR/v1.18/desktop-pet-tech-design-v1.18.md)
- **上一版本**：[v1.16](../v1.16/desktop-pet-PRD-v1.16.md)
- **状态**：待评审
- **变更性质**：自主行为能力扩展（不改状态机白名单、不改数值语义）

## 0. 用户反馈

> 「不要这些 我希望这些状态都可以出现」

上一版解释了「`EATING` 要投喂、`HURT` 要单击、`THINKING/SPEAKING` 要发消息、`SLEEPING` 要夜间」，用户明确**不接受这种依赖交互的口径**：要求桌宠自己就能轮到全部状态，而不是靠人去点。

## 1. C27 全状态自主轮播

### R1 自主动作池扩到全部一次性状态
`STRETCHING / EATING / HURT / SPEAKING / THINKING / SLEEPING / SAD` 纳入自主行为，**按固定顺序轮播**（不是概率抽样），保证每个状态都会被轮到，不会出现「概率太低长期看不见」。

### R2 保持活物节奏
每两次自主触发中一次做轮播演示，另一次仍是走/跑；走路待机仍是主体，不变成机械的状态轮播。

### R3 不破坏既有概率语义
轮播不额外调用随机数，`stretch_trigger_p` / `run_trigger_p` / `TRIP_END_CHANCE` 的判定与随机顺序完全不变。

### R4 所有一次性状态都能自己收场
`ONE_SHOT_MIN_DURATION_S` 补齐 `SPEAKING / THINKING / SAD`，仍按整圈时长向上取整。`THINKING` 因 `Pet.finish_action()` 的集合里没有它，单独走 `THINKING→IDLE` 白名单迁移。夜间睡眠仍按「天亮即醒」，白天轮播打盹睡满 6 秒再醒（两者用入睡时是否夜间区分）。

### R5 纯动画演示，不改数值
自主触发的 `EATING / HURT / SPEAKING / THINKING` 只切动画状态：**不喂食、不扣心情、不发 AI 请求、不弹气泡**；用户交互仍照常触发真实语义（投喂涨饱食、点击扣心情、发消息走 AI）。

### R6 拖拽例外
`DRAGGING` 是用户手在拖，不属于自主行为，仍只在交互时出现。

### 验收项
- AC-SHOW-1：轮播顺序覆盖全部 7 个一次性状态，且循环可回收。
- AC-SHOW-2：`SPEAKING / THINKING / SAD` 都能在播完后自动回到 `IDLE`。
- AC-SHOW-3：白天打盹至少停留 6 秒，不被下一拍立刻叫醒；夜间睡到天亮的既有行为不变。
- AC-SHOW-4：既有 `stretch/run` 概率测试、睡醒求助时序、轮询节奏测试全部继续通过。
- AC-SHOW-5：长时间空跑（不交互）能看到全部 10 个动作状态。

## 2. 不作废的旧约束

- 状态机 `ALLOWED_TRANSITIONS` / `LOCKED_STATES` / `AUTONOMOUS_TARGETS` 不变；轮播全部走 `IDLE` 出发的合法迁移。
- FR v1.16 C26 的 SAD 冷却与夜间睡觉解锁、FR v1.15 C25 的轮询节奏不变。
- 按天记录、会话恢复、对话冻结、逐动作帧率、一次性动作整圈收场不变。

## 3. 范围外

- 自主演示时附带气泡台词 / 自言自语（会打扰用户，且与真实聊天混淆）。
- 让自主 `EATING` / `HURT` 改动三维数值（会架空投喂/抚摸的意义）。
- 可配置的轮播频率与顺序（先按固定节奏，需要再评审）。
