## 1. C42：把路线图的 P0 / P1 / P2 落到可验证的代码

用户要求「P0 P1 P2 都做了」。本版按「先可交付、再可发现、后差异化」的顺序落地，
并明确区分**能在本环境完成**与**需要证书/真机/外部服务**的项。

## 2. 明确的范围外 / 环境阻塞（不假装完成）

| 项 | 原因 |
|---|---|
| macOS 代码签名与公证的**证书、公证流程、双平台干净机器双击验证** | 需要 Apple Developer 账号与 macOS 机器；脚本已有 `WISEPET_CODESIGN_IDENTITY` 开关，缺的是凭据与真机 |
| AI 素材补图（dog / monkey 换成与 cat 同批画风） | 生成通道不支持参考图；本版只交付规格闸，规格合格 ≠ 画风一致 |
| 天气 / 日历外部 API | 与「零新依赖、断网可用」底线冲突；本版用系统空闲等本机事实兑现因果驱动 |
| 助理任务队列 / 失败重试 / 第三方 action 沙箱 | 超出本批，已有执行历史与三级权限作为前置 |
| 自动更新、发布通道、皮肤工坊、插件市场、手机伴侣 | 属 P3，触发条件（安装成功率 / D7 留存）尚未达标 |

## 3. 不变的底线

不新增任何三方依赖（sqlite3 / ctypes 均为标准库）、不上传任何数据、不改状态机白名单与事件契约、
`config.json` 仍可读可手改、BYOK 永远保留。
