## 1. C43 macOS 发布通道：签名与公证接线

### 背景

用户指出 macOS 包不必在本机做——CI 的 `macos-latest` runner 就是一台干净的 mac，
把凭据放进仓库 secrets，推 tag 即可出签名公证的 dmg。本机（Windows）**不能**交叉编译，
但可以把链路准备好。

### 需求

| 编号 | 需求 | 验收项 |
|---|---|---|
| R1 | 脚本支持 dmg 签名：`sign_dmg()` 对 hdiutil 产物加 runtime 签名，否则公证必被 Apple 拒收 | AC-PUB-1：未配 `WISEPET_CODESIGN_IDENTITY` 时整步跳过、不报错 |
| R2 | 脚本支持公证：`notarize_dmg()` 走 `xcrun notarytool submit --wait` + `stapler staple` | AC-PUB-2：仅 `WISEPET_NOTARIZE=1` 且三项 Apple 凭据齐全才调用 `xcrun`；凭据走环境变量、不落盘、不打印明文 |
| R3 | CI 注入签名/公证 secrets，并按需导入 p12 证书到临时钥匙串 | AC-PUB-3：未配 `MACOS_CERTIFICATE` 时导入步骤跳过，自动降级为未签名 dmg |
| R4 | 未配凭据时行为不变：出未签名 dmg（右键→打开可用），不假装完成 | AC-PUB-4：CI 双平台矩阵仍各自产出、不中断 |
| R4a | **workflow 必须能被 GitHub 正常解析**：`if:` 不引用 `secrets` context，证书存在性判断放 shell（补登，编号避开 C44 的 R5） | AC-PUB-5：见下方「CI 语法修复」——用户推送时曾报 `Unrecognized named-value: 'secrets'` |

### CI 语法修复（用户推送时报错，补登）

首次推送时 GitHub 报：
`Invalid workflow file ... (Line: 34, Col: 13): Unrecognized named-value: 'secrets'`。
根因：证书导入 step 写成 `if: matrix.target == 'macos' && secrets.MACOS_CERTIFICATE != ''`，
而 GitHub Actions 的 `if:` **不允许引用 `secrets` context**（只允许
`github/needs/strategy/matrix/job/runner/env/vars/steps/inputs`），整个 workflow 解析失败。
改为 `if: matrix.target == 'macos'`，证书存在性判断挪进 shell（`-z` 检测 + `exit 0` 跳过）；
同段把 `base64 --decode`（GNU）换成 Python `base64.b64decode`，因为 macOS runner 自带 BSD
`base64` 不支持该长选项。新增 7 项纯标准库静态护栏（本机无 actionlint/PyYAML，真解析仍以 GitHub 为准）。

### 范围外（不假装完成）

- **Apple Developer 账号、`Developer ID Application` 证书、公证权限**属 Apple 硬性要求，
  CI 无法代替用户申请；凭据只存在用户仓库 secrets，不进源码也不进日志。
- **双平台真机双击验证**仍需人工：本机是 Windows + offscreen，macOS 签名/公证分支
  只验证了命令拼接与开关逻辑，未做真机公证提交。

## 2. C44 登场特效体系：7 种主体 + 随触发 + 随机

### 背景（三轮用户反馈）

1. 「加 5 个宠物进入的特效，随触发」→ 从单一 `spawn` 扩成多种。
2. 「不要一个风格的，想想新奇的方式」→ 主体必须风格各异，不能只是同一套粒子换色。
3. 「隐藏和出现宠物还是两个特效，其他的没出现」→ 根因：只在「隐藏→显示」过渡播放，
   日常宠物一直可见，`chat/scene/celebrate` 三条触发被整段跳过。
4. 「隐藏出现宠物也要随机播放特效」→ 恢复显示不再固定一种。

### 需求

| 编号 | 需求 | 验收项 |
|---|---|---|
| R5 | 7 种主体风格：粒子汇聚 / 粒子爆开 / 三角碎片拼合 / HUD 扫描 / 双向能量揭幕 / 同心能量波纹 / 聚焦光束 | AC-FX-1：每种在各阶段绘制不报错，`ENTER_KINDS` 与设置项一一对应 |
| R6 | **随触发**：`auto` 按场景分派（boot/chat/scene/celebrate），其余动作在宠物已可见时也播特效层反馈 | AC-FX-2：可见时播反馈层且不隐藏宠物、不重播登场；隐藏时才走完整登场 |
| R7 | **隐藏/出现随机**：`auto` 下 toggle 每次随机；另提供 `random` 模式所有触发都随机 | AC-FX-3：随机池覆盖全部 7 种；手动固定某一种时各触发都返回该值 |
| R8 | 可配置：`PetParams.enter_effect`（auto / random / 7 种），设置窗「宠物参数 → 进入特效」共 9 项 | AC-FX-4：非法值回落 auto、保存后重启保持、无关保存不丢字段 |
| R9 | 退场（隐藏 / 退出）仍播粒子消散，与进入互不影响 | AC-FX-5：退场只在结束时发一次 `finished`（退出程序依赖它） |

### 取舍

- 不做「无差别随机」：用户既要「随触发」又要「隐藏出现随机」，故 `auto` 只对 toggle 随机、
  其余按场景固定可解释，另单独提供 `random` 让用户主动选。
- 不做「已可见宠物也重播完整登场」：会闪烁，改为只播独立透明叠加的特效层。

## 3. C45 出场动画整体优化（本轮重点）

### 背景

用户反馈「现在的这几个出场效果和之前最开始的程序出场效果动画差太多了」。
实证定位两条差距，**都不是风格问题，是质量与结构问题**：

| 问题 | 实证 | 后果 |
|---|---|---|
| **绘制期每帧随机** | `puzzle/terminal/ink/magnifier` 的 paint 里逐帧调 `self._rng.*` 生成碎片落点、字符、波纹配色、光束高度 | 同一进度每帧内容都不同 → 动画在抖，观感廉价 |
| **没有统一骨架** | 只有 `spawn` 有「汇聚环 + 扫描环 + 白核爆闪」；其余 6 种各画各的，时长 780~950ms 不齐、硬起硬停 | 与最初开机动画（FR v1.20 C37）三段式叙事割裂 |

### 需求

| 编号 | 需求 | 验收项 |
|---|---|---|
| R10 | **绘制期零随机**：所有随机参数在 `TechEffect.__init__` 一次生成并缓存，paint 阶段只读 | AC-OPT-1：同一进度连画两帧像素完全一致（7 种 + exit 全覆盖，各取 3 个进度） |
| R11 | **统一三段式骨架**：7 种共享「汇聚能量环 + 旋转扫描环 → 各风格主体 → 收尾白核爆闪 + 十字准星」 | AC-OPT-2：每种在 66% 之后都走同一套收尾；`MAIN_END` 为单一常量 |
| R12 | **节奏对齐最初**：所有进入特效统一 950ms（沿用 C37），退场仍 700ms | AC-OPT-3：时长表值集合为 `{950}`、`950 > 700` |
| R13 | **首尾渐入渐出**，消除硬起硬停 | AC-OPT-4：`_envelope(0)==0`、`_envelope(1)==0`、中段为 1 |
| R14 | **淡入与爆闪重叠**：进入特效在 82% 处提前发 `finished`，宠物 220ms 淡入与收尾爆闪重叠，不留空白帧 | AC-OPT-5：提前只发一次 `finished`；结束不重复发；退场不提前发 |

### R15 三角碎片配色修正（用户真机目检反馈）

用户反馈「出现三角的那个三角配色不好看」。实证是**配色 bug 而非单纯审美**：
`puzzle` 把非青碎片的亮部写成 `CYAN_DARK(20,80,100)`、渐变到 `ORANGE_DARK(120,70,30)`，
青碎片也是亮青→暗青，等于一块**不透明暗色实心三角**；而整套其他特效都是
「发光描边 + 半透明光晕」，唯独它是色块，显得脏且与统一骨架割裂。
改为只用 `PUZZLE_TONES = (CYAN, ORANGE)` 两种亮色：满 alpha 亮色描边 +
从 42% 亮色渐隐到全透明的填充，与粒子/光晕的光效语言一致。删除两个不再使用的暗色常量。

- AC-OPT-6：`PUZZLE_TONES` 只含两种亮色（每色亮度足够高）、填充末端全透明、
  逐帧像素确定性不回归。

### 不变项（守住前几轮结论）

- 7 种**主体风格差异保留**——统一的是骨架，不是把 7 种画成一种。
- 随触发 / 随机 / 可固定 / 退场语义全部不变。
- 零额外素材、零新增三方依赖、不改状态机与事件契约。

## 5. 仍然阻塞（如实登记）

| 项 | 原因 |
|---|---|
| 出场动画**真机目检** | 本机 Windows + offscreen 只能验证「不抛异常 + 像素确定性 + 时序」，无法判断观感；统一骨架后的实际流畅度、配色、爆闪强度需真机确认 |
| macOS 签名公证**真机提交** | 需 Apple 账号与证书，本机无凭据、无 mac runner 实跑 |
| 自动更新 / 皮肤工坊 / 插件 / STT / 手机伴侣 | 属 P3 或依赖发布基础设施，触发条件（安装成功率、D7 留存）仍无真机读数 |
