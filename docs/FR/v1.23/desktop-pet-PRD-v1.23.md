## 1. C40：日志分等级、单文件 10 MiB 分割、只保留近 3 天

旧实现是单文件 `WisePet.log`，`RotatingFileHandler` 1 MB × 3 份备份：
没有分级、按**文件数**保留而不是按时间、且低日志量时旧内容可能长期滞留。

| 编号 | 需求 | 验收项 |
|---|---|---|
| R1 | **日志分等级**：主档保留完整时间线，告警与错误单独成档 | AC-LOG-1~2：`WisePet.log` 收 INFO+（含 WARNING/ERROR），`WisePet-error.log` 只收 WARNING+；`setup_logging()` 仍返回主档路径；重复调用不叠加 handler |
| R2 | **单个文件超过 10 MiB 就分割** | AC-LOG-3~4：阈值为 `10 * 1024 * 1024`；写满后产生 `.1` 备份且当前文件继续可写；两个档各自独立滚动 |
| R3 | **只保留近 3 天的日志** | AC-LOG-5~8：超过 3 天的滚动备份自动删除、3 天内的保留；正在写的文件永不删；**日志量不到 10 MiB 时也要跨天封存**，否则旧内容赖在当前文件里删不掉；未发生滚动时也会按自然日兜底清理 |
| R4 | 分级后脱敏不降级 | AC-LOG-9：两档都挂 `SecretMaskFilter`，`sk-*` / `Bearer *` 仍不明文落盘；既有 16 项日志契约除幂等断言外不变 |

## 2. 边界

- **不改日志内容格式**（`%(asctime)s %(levelname)s [%(name)s] %(message)s`）、不改启动日志路径打印、
  不改 `main.py` 的 `setup_logging()` 调用方式。
- **不做四级互斥分文件**：看完整时间线要拼四个文件，且会破坏所有读 `WisePet.log` 的既有契约；
  「主档全量 + 错误档单独」兼顾排障效率与向后兼容。
- 不改聊天记录数据库与其它持久化；日志只在本机滚动，不上传。
- 备份数保留一个大的硬上限（200）作为极端写入兜底，但正常清理完全按时间口径。

## 3. 用户可见变化

`docs/设置手册.md` §七 文件位置新增 `WisePet-error.log`；排障时建议：
按 `ReminderDueEvent` / `behavior … -> …` 查主档，按超时、异常、`protocol` 错误查错误档。
